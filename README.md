# LamoFrame — Next.js + PGlite

Самостоятельный перенос исходного конструктора. Для запуска не нужны Django,
Python или отдельный сервер PostgreSQL. Python 3 нужен только для однократного
импорта старой SQLite-базы.

## Запуск

```sh
cd nextjs
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Если `.env.local` уже существует, сохраните его:
локальная конфигурация подготовлена при переносе.

В `storage/pglite` хранится PostgreSQL-база PGlite, в `storage/media` — изображения.
Данные сохраняются между перезапусками. В рабочую папку уже импортированы
2 пользователя и 2 проекта из `app/db.sqlite3`. Существующие логины и пароли
PBKDF2 работают; войдите повторно, старые Django-сессии не переносятся.
`storage` исключена из Git: для переноса на другой компьютер нужен её бэкап.

## Что перенесено

- Вход, регистрация, выход, необязательный вход Google.
- Поиск, создание, дублирование и удаление проектов; превью карточек.
- Пустой холст, три обычных шаблона и «Аналитика B2B».
- Полный редактор: фреймы, слои, группы, история, привязки, страницы,
  адаптивные макеты, компоненты, изображения, анимации и горячие клавиши.
- Автосохранение с проверкой версии; самостоятельные HTML и ZIP.
- Публичное превью с sandbox CSP и ETag.
- Коллекции, пять типов полей, связи, записи и проверка данных.
- Публикация снимка приложения отдельно от черновика; живые записи.
- Одноразовые приглашения на 7 дней, роли editor/viewer, отзыв доступа.
- Админка `/admin/`: пользователи, проекты, файлы и шаблоны.

Next.js App Router обслуживает HTML и API через Node.js Route Handler.
Серверные модули написаны на JavaScript; HTML рендерится Nunjucks, а существующий
редактор работает как ES-модули. Его код и CSS сохранены, чтобы перенести все
возможности холста. Схема документа v1–v3 и адреса приложения совместимы
с исходной версией. Подробный разбор — в [ANALYSIS.md](ANALYSIS.md).

## Импорт другой Django-базы

Остановите сервер. Укажите новую пустую папку хранения:

```sh
STORAGE_DIR=./storage-import npm run import:django -- /absolute/path/db.sqlite3
```

Импорт читает исходную SQLite в режиме read-only, копирует пользователей,
PBKDF2-пароли, Google ID, проекты, шаблоны, изображения, коллекции, поля,
записи, публикации, участников и приглашения. Сохраняет ID и исправляет
последовательности PostgreSQL. Медиа берутся из папки `media` рядом с SQLite.
Если в целевой базе уже есть пользователи или проекты, импорт останавливается.
После успешного импорта задайте тот же `STORAGE_DIR` в `.env.local`.

Команды Node-скриптов читают переменные окружения оболочки. Для них передавайте
`STORAGE_DIR` явно; `.env.local` автоматически читает именно сервер Next.js.

## Демо и администратор

На остановленном сервере:

```sh
DEMO_PASSWORD='your-demo-password' ADMIN_PASSWORD='your-admin-password' npm run seed
```

Создаёт `demo`, пример лендинга и `admin`, если они ещё не существуют.
Пароли существующих пользователей не заменяются. Без `DEMO_PASSWORD`
демо-пароль генерируется и выводится один раз. Администратор создаётся только
при заданном `ADMIN_PASSWORD`. У импортированного Django staff права сохраняются.

## Google OAuth

Кнопка входа через Google по умолчанию скрыта. Чтобы вернуть её, задайте
`SHOW_GOOGLE_LOGIN=true` в `.env.local` и перезапустите сервер (для production
повторите сборку). Реализация OAuth сохранена.

Также задайте `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` и `APP_URL`.
В Google Console укажите callback:

```text
http://localhost:3000/accounts/google/login/callback/
```

Для production используйте свой HTTPS-домен. Без ключей кнопка скрыта.
OAuth использует одноразовый state, HttpOnly cookie, обмен code на сервере и
проверенный Google email. Автоматическое связывание с локальным аккаунтом
с таким же email не выполняется. Внешний вход требует настоящих ключей и
не проверялся реальным Google-аккаунтом при переносе.

## Проверки

```sh
npm test
npm run build
npm run test:browser
```

Для браузерных тестов предварительно установите Chromium:
`npx playwright install chromium`. На macOS можно использовать установленный Chrome:

```sh
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run test:browser
```

Playwright самостоятельно запускает сервер на порту 3100 с отдельной временной
базой. Серверные тесты также используют временную базу. Рабочие проекты не меняются.

## Production

```sh
npm run build
npm start
# или
 docker compose up --build
```

PGlite использует файловую систему Node.js: запускайте **один серверный процесс**
на одну папку базы. Для горизонтального масштабирования потребуется обычный
PostgreSQL. Среда с эфемерным диском без постоянного volume не сохраняет данные.
Не запускайте импорт/seed одновременно с сервером на одной папке PGlite.

Для HTTPS установите `COOKIE_SECURE=true`, `APP_URL=https://ваш-домен`.
`COOKIE_SECURE=false` в примере предназначен для локального HTTP.
Docker Compose сохраняет базу и медиа в volume `lamoframe-data`.
Для резервной копии остановите сервер и скопируйте всю `storage`.

## Сохранение, восстановление и публикация

Автосохранение отправляет только JSON холста и название. Подготовка HTML,
изображений и ZIP выполняется отдельно: ошибка или превышение лимита HTML
не блокируют сохранение черновика. Серверный HTML-экспорт собирается из
текущего сохранённого документа по запросу.

В браузере IndexedDB хранит несохранённые копии отдельно для каждого аккаунта,
проекта и вкладки. После сбоя редактор предлагает восстановить копию, скачать
её в JSON или оставить серверную версию. После успешного сохранения соответствующая
локальная копия удаляется. При недоступном IndexedDB показывается предупреждение.
Локальная копия не заменяет резервную копию базы; очистка данных браузера удаляет её.

При конфликте двух вкладок автоматическое сохранение останавливается.
Можно скачать свою работу в JSON, обновить страницу и выбрать нужную копию.

Кнопка **Версии** открывает последние 30 автоматических снимков (не чаще одного
в минуту) и до 50 именованных версий. Перед восстановлением автоматически
создаётся страховочная версия. Восстанавливаются название и холст;
схемы коллекций, записи, участники и опубликованные снимки не заменяются.
Версии доступны только владельцу проекта, их можно скачать или удалить.

Кнопка **Публикация** у сайта создаёт отдельный публичный снимок. Сохранение
и ZIP не публикуют сайт. Изменения черновика не видны посетителям до обновления
публикации. Кнопка «Снять с публикации» отключает публичный адрес.
Снимок включает загруженные в проект изображения; внешние URL остаются внешними.
Для приложений с коллекциями по-прежнему используется публикация в «Данные и доступ».

При обновлении старые `exported_html` сохраняются в базе для совместимости,
но **общий доступ нужно включить явно** через «Публикация».
Новые таблицы добавляются автоматически при запуске через нумерованную
транзакционную миграцию `lib/migrations.mjs`, данные проектов не заменяются.

Во вкладке **Адаптив → Проверить макеты** доступны замечания о выходе элементов
за границы секций, пустых изображениях и ссылках. Нажатие выделяет проблемный
элемент. Проверка геометрии учитывает поворот и ручные макеты устройств;
она не симулирует автоматический reflow и не заменяет визуальную проверку превью.

## Шаблон CRM продаж

На странице создания выберите **CRM продаж**. Будут созданы пять страниц:
«Обзор», «Клиенты», «Сделки», «Задачи», «Настройки CRM», общий sidebar и четыре
связанные коллекции: клиенты, сделки, задачи и сотрудники. Флажок
«Заполнить демонстрационными данными» создаёт примеры; его можно снять для пустой CRM.
Шаблон открывается в редакторе и не публикуется автоматически.

В «Обзоре» показатели и диаграммы рассчитываются по записям. Есть период
«Всё время / 30 дней / 7 дней». Выручка — сумма выигранных сделок по дате
закрытия; открытые сделки исключают выигранные и проигранные. Таблицы
поддерживают поиск, фильтр статуса, сортировку и переход к карточке.
Канбан позволяет менять этап перетаскиванием или выпадающим списком.
После изменения этапа CRM обновляет данные и аналитику; другие участники
могут получить изменения кнопкой «Обновить данные».

В карточке видны связанные записи и кнопки создания связанных сделок/задач
с уже выбранным клиентом. Доступны комментарии, история изменений и удаление.
Удаление блокируется, если на запись ссылаются другие записи.
Статусы/этапы меняются владельцем в «Данные и доступ → Изменить статусы»;
после изменения нужно повторно опубликовать приложение.
Нельзя убрать статус, который ещё используется записями.

«Сотрудники» — справочник для назначения ответственных. Доступ к самой CRM
выдаётся отдельно приглашениями editor/viewer. Наблюдатели не могут менять
записи или оставлять комментарии. Версия записи защищает изменения от
перезаписи другим участником. Все эти проверки выполняются сервером.

Виджеты «Метрика», «График» и «Канбан» имеют настройки привязки к коллекции
в правой панели. Можно изменять поля, страницы, названия и состав виджетов.
Канбан также доступен в библиотеке слева. Изменения макета вступают в силу
после публикации, записи при этом сохраняются.

## Общий sidebar и тема готового сайта

Слева в библиотеке есть блок **Общий sidebar**. Он один для всех страниц,
автоматически строит ссылки из списка страниц и подсвечивает текущую.
Настройки находятся в правой панели **Будущий сайт**:

- тема: «Светлая», «Тёмная» или «С переключателем»;
- включение sidebar, название и начальная ширина 180–360 px;
- «Поток для приложений»: перестройка карточек, диаграмм и таблиц по доступной ширине.

Sidebar резервирует часть ширины всех десктопных/планшетных секций, включая
новые секции. В свободном макете координаты пересчитываются пропорционально;
в режиме потока готовое приложение использует адаптивную сетку. Поток включён
в CRM по умолчанию и меняет способ раскладки виджетов при выводе.

Посетитель может тянуть границу меню, менять ширину клавишами стрелок,
сворачивать меню и переключать тему (если автор выбрал этот режим).
Его настройки сохраняются в браузере отдельно от документа автора.
На телефоне sidebar становится выдвижным меню. Эти функции работают
в предпросмотре, публикации и многостраничном ZIP обычного сайта.
CRM с живыми данными запускается на сервере, а не экспортируется в статический ZIP.

Тема редактора и тема готового сайта независимы. Тёмная тема переоформляет
навигацию, секции, текст и стандартные виджеты. Изображения и авторские
декоративные цвета не заменяются автоматически; результат стоит проверить
в превью. Персональные настройки не переживут очистку данных браузера.

Миграция 2 добавляет версии записей и журнал событий без замены существующих данных.
