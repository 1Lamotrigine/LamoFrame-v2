# LamoFrame — локальный конструктор сайтов и CRM

Next.js отдаёт интерфейс и статические файлы. **PGlite работает в браузере,
в Web Worker, и сохраняет данные в IndexedDB.** Не нужны PostgreSQL, серверная
база, переменные подключения или записываемый диск на Vercel.

## Запуск локально

```sh
cd nextjs
npm ci
npm run dev
```

Откройте http://localhost:3000 и создайте локальный профиль. При первом запуске
браузер загружает движок PGlite и WebAssembly — это занимает немного времени.

```sh
npm run build
npm start
```

Один и тот же браузерный режим используется в разработке и production.
Команды dev/build автоматически собирают браузерные модули, шаблоны и ресурсы
PGlite в `public/local`; эта папка генерируется и не хранится в Git.
Для сборки нужны devDependencies (включая esbuild). После изменения браузерной
логики или HTML-шаблонов выполните `npm run build:browser` либо перезапустите dev.

## Vercel

1. Загрузите изменения в GitHub.
2. В проекте Vercel выберите **Root Directory: nextjs**.
3. Framework Preset: **Next.js**, Build Command: `npm run build`.
4. Запустите Redeploy. Если изменён Install Command, используйте `npm ci --include=dev`.

`DATABASE_URL`, `STORAGE_DIR`, Google OAuth и серверные cookies для этого
режима не нужны. Каталог `storage` не загружается на Vercel и не используется
опубликованным приложением. Каждый посетитель получает свою локальную мастерскую.

## Локальные профили и данные

- Профиль не является защищённым аккаунтом и не требует пароля.
- Пользователи одного браузера могут переключаться между локальными профилями.
- Все записи, проекты, изображения, версии и рабочие снимки остаются на устройстве.
- Перезагрузка страницы и обычное закрытие браузера сохраняют данные.
- Данные разделены по origin: localhost, Vercel и разные домены — разные хранилища.
- Другой браузер или устройство не увидит вашу мастерскую автоматически.
- Очистка данных браузера, приватный режим или удаление хранилища могут стереть данные.
- Google-вход, приглашения и серверная совместная работа отключены.
- Профиль не является границей безопасности: любой пользователь этого браузера
  может открыть остальные локальные профили.

Используйте актуальный Chrome, Edge или Firefox с разрешёнными IndexedDB,
SharedWorker и Web Locks. На Vercel нужен HTTPS; localhost подходит для разработки.
База обслуживается одним SharedWorker PGlite: вкладки используют
согласованный доступ к одной базе. Закрытие одной вкладки не останавливает базу
в остальных; незавершённая транзакция закрытой вкладки откатывается. Изменяющие операции и резервные копии дополнительно
согласуются через Web Locks. Переход на другую вкладку не создаёт новую базу.

Это не полный offline-first режим: для открытия приложения нужны статические
ресурсы сайта. Данные не отправляются в облако, но полное кеширование приложения
для первого запуска без сети не реализовано.

## Резервное копирование и перенос

На дашборде есть **Резервная копия**. Скачивается JSON всей мастерской:
профили, проекты, файлы, коллекции, записи CRM, опубликованные локальные снимки,
история версий и событий. Не публикуйте этот файл: он содержит ваши данные.

Для переноса с localhost на Vercel или на другой компьютер:

1. Скачайте полную копию на исходном устройстве.
2. Откройте LamoFrame по новому адресу.
3. Выберите «Перенести мастерскую из резервной копии» или «Резервная копия».
4. Выберите файл и подтвердите замену текущей мастерской.

Восстановление проверяет формат и выполняется одной транзакцией PGlite.
При ошибке текущие данные остаются на месте. Импорт заменяет всю мастерскую,
поэтому перед ним скачайте текущую копию. Максимальный размер файла — 100 МБ.
После импорта выберите восстановленный профиль. Старые локальные аварийные
копии редактора отделяются от восстановленной мастерской.

### Переход с прежней серверной версии

Старый каталог `storage` оставлен нетронутым. Для переноса прежних проектов:

```sh
npm run export:browser
```

Команда создаёт `storage/browser-workspace.json`. Импортируйте его через
интерфейс. Пароли и Google-привязки не переносятся; пользователи становятся
локальными профилями. Не копируйте эту копию в `public` и не добавляйте её в Git.
Прежние скрипты импорта Django оставлены для подготовки/конвертации старой
серверной базы; они не используются на Vercel.

## Возможности

- Создание, поиск, дублирование и удаление проектов.
- Многостраничный редактор: секции, элементы, история, компоненты, адаптив,
  изображения, горячие клавиши, анимации и локальное аварийное восстановление.
- Шаблон «CRM продаж»: обзор, клиенты, сделки, задачи, настройки и демоданные по выбору.
- Связанные коллекции, канбан, таблицы, фильтры, сортировка, диаграммы и показатели.
- Карточки записей, комментарии и история действий; защита связанных записей от удаления.
- Общий sidebar, изменение ширины, сворачивание и мобильное меню.
- Светлая, тёмная или переключаемая тема будущего сайта независимо от темы редактора.
- Автоматические и именованные версии холста, локальные рабочие снимки.
- HTML и многостраничный ZIP обычного сайта.

«Публикация» в локальном режиме означает **локальный рабочий снимок**.
Ссылки на CRM и превью работают только в браузере, где находится мастерская.
Чтобы поделиться обычным сайтом, скачайте HTML/ZIP и разместите его отдельно.
CRM с данными переносится полной резервной копией, а не статическим ZIP.
Справочник сотрудников в CRM используется для назначения ответственных,
а не для выдачи доступа другим устройствам.

## Проверки

```sh
npm test
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run test:browser
npm run build
```

Без установленного Chrome предварительно выполните `npx playwright install chromium`.
Браузерные тесты проверяют именно IndexedDB-режим, включая закрытие вкладки
с незавершённой транзакцией и откат повреждённой резервной копии; Node-тесты сохраняют проверки
общей предметной логики и конвертации прежней базы. Предыдущие серверные
браузерные сценарии сохранены как справочные и не запускаются default-конфигурацией.

Архитектура описана в [ANALYSIS.md](ANALYSIS.md).
